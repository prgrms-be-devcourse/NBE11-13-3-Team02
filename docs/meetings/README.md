# 회의록 → 할 일 자동 정리

회의에서 정한 것이 각자의 머릿속에만 남으면, 다음 회의가 "그거 누가 하기로
했었죠?"부터 시작합니다. 회의록만 남기면 나머지는 도구가 합니다.

```
회의록 작성  →  AI 정리  →  미리보기 확인  →  GitHub 이슈
```

---

## 처음 한 번만

```bash
# 1. uv 설치 (이미 있으면 건너뛰기)
brew install uv

# 2. GEMINI_API_KEY 확인 — .env.local 에 있어야 합니다
cd /경로/NBE11-13-3-Team02 && grep -q '^GEMINI_API_KEY=.' .env.local && echo OK || echo "./setup.sh 를 먼저 실행하세요"

# 3. gh 로그인 (이슈를 만들 때만 필요)
gh auth status || gh auth login
```

`GEMINI_API_KEY` 는 개인 발급 무료 키입니다. 없으면
[aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 만들어
`.env.local` 에 넣으세요.

## 매 회의마다

### 1. 회의록 쓰기

```bash
cp docs/meetings/TEMPLATE.md docs/meetings/2026-09-20.md
```

**형식을 맞추려고 애쓰지 마세요.** 들은 대로 적으면 됩니다. 정리는 도구가 합니다.

다만 이 두 가지는 적어야 도구도 압니다.

| 적어야 할 것 | 예 |
| --- | --- |
| 누가 맡기로 했는지 | "이건 석우님이 보기로" |
| 정해진 것과 안 정해진 것 | "이건 다음에 정하자" |

담당자를 안 적으면 `미정` 으로 나옵니다. 지어내지 않습니다.

### 2. 정리 결과 보기

```bash
uv run tools/meeting_notes.py docs/meetings/2026-09-20.md
```

네 갈래로 나옵니다.

| 항목 | 내용 |
| --- | --- |
| 요약 | 무엇을 다뤘고 무엇이 정해졌는지 3문장 이내 |
| 결정사항 | **확정된 것만** |
| 보류 | 논의했으나 결론이 안 나 다음으로 넘긴 것 |
| 담당자별 할 일 | 담당자 · 완료 조건 · 기한 |

### 3. 이슈로 올릴 내용 미리 보기

```bash
uv run tools/meeting_notes.py docs/meetings/2026-09-20.md --issues
```

`gh issue create` 명령을 출력만 합니다. **아무것도 만들지 않습니다.**

### 4. 확인했으면 실제로 만들기

```bash
uv run tools/meeting_notes.py docs/meetings/2026-09-20.md --create
```

`이슈 N건을 실제로 만듭니다. 진행할까요? [y/N]` 에서 `y` 를 입력하면 만들어집니다.

> **터미널에서 직접 실행하세요.** 에디터의 실행 버튼은 이 입력을 받지 못합니다.

## 알아두면 좋은 것

**결과가 매번 조금씩 다릅니다.** 같은 회의록이어도 항목 수나 묶는 방식이 달라집니다.
LLM 이라 어쩔 수 없습니다. **초안으로 쓰고 사람이 다듬는다**는 전제이고, 그래서
이슈를 만들기 전에 `--issues` 로 확인하는 단계가 있습니다.

**지어내지 않게 하는 장치가 둘 있습니다.**

- 출력 형태를 스키마로 고정해 파싱이 결정적입니다.
- 담당자는 팀원 목록 안에서만 고릅니다. 회의록에서 분명하지 않으면 `미정` 입니다.
  엉뚱한 사람에게 일이 배정되는 것보다 비어 있는 편이 낫습니다.

**담당자는 GitHub assignee 로도 걸립니다.** 회의록의 한글 이름을 계정에 이어 둡니다.

| 이름 | GitHub |
| --- | --- |
| 안서호 | `ahnseho02` |
| 이석우 | `lucku-1111` |
| 김주형 | `JuhyungKim-dev` |

지정에 실패하면(협업자가 아니거나 계정명이 바뀐 경우) 안내를 남기고 **담당자 없이
이슈는 만듭니다.** 담당자 하나 때문에 이슈까지 못 만드는 게 더 손해이기 때문입니다.

**팀원을 추가하려면** `tools/meeting_notes.py` 의 `MEMBERS` 와 `GITHUB_HANDLES` 에
넣으세요. 둘 다 넣어야 담당자까지 걸립니다.

**이슈는 삭제가 안 됩니다.** 조직 리포지토리라 관리자만 지울 수 있습니다. 잘못 만들었으면
`gh issue close <번호>` 로 닫으세요.

## 잘 안 될 때

| 증상 | 원인 |
| --- | --- |
| `GEMINI_API_KEY 를 찾지 못했습니다` | `.env.local` 에 키가 없습니다. `./setup.sh` 실행 |
| `429 RESOURCE_EXHAUSTED` | 무료 한도 소진. 생성 모델은 하루 20회입니다 |
| `y` 를 눌러도 반응이 없음 | 에디터 실행 버튼으로 돌렸을 가능성. 터미널에서 실행 |
| 이슈가 안 만들어짐 | `gh auth status` 로 로그인 확인 |
